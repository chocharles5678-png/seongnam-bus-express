# 공공데이터 수집

성남 버스 분석에서 실제로 낸 실수에서 나왔다. 수집 자체보다 **수집한 값을 믿어도 되는가**가 어렵다.

---

## 0. 크롤링 전에 — 공식 API가 있는가

**있으면 크롤링하지 않는다.** 공모전·논문·제출물 규정은 대체로 이렇게 쓰여 있다.

> 접근권한 우회, 무단 계정 사용, 이용약관에 위배되는 자동수집 또는 크롤링 등
> 부적절한 방법으로 데이터를 수집해서는 안 됩니다.

성남 분석은 **공공데이터포털 활용신청 → 인증키 → 공식 OpenAPI** 로만 받았다.
HTML 파싱은 한 번도 하지 않았고, 그래서 "적법한 취득" 질문에 답할 게 있었다.

크롤링이 불가피하면 **먼저 적어둔다** — 대상 사이트의 `robots.txt`, 이용약관의 자동수집 조항,
요청 간격, 수집 범위. 결과물에 출처·수집 방법·기준시점을 밝혀야 하므로 나중에 복원할 수 없다.

---

## 1. 호출 예산을 먼저 계산한다

개발계정은 대개 **하루 1,000회**다. 폴링은 이 한도를 순식간에 태운다.

```python
need = (minutes * 60 // interval) * len(targets)
print(f'예상 호출 {need}회 (예산 {budget})')
if need > budget:
    print(f'⚠ 예산 초과. 간격을 {minutes*60*len(targets)//budget}초 이상으로')
```

**실행 중에도 센다.** `while time.time() < end and calls < budget:` —
시간 조건만 걸면 오류 재시도로 한도를 넘긴다.

여러 노선을 동시에 폴링하면 **호출이 노선 수만큼 곱해진다.** 2노선 30초 간격 2시간 = 480회다.

---

## 2. 인증키는 코드에 넣지 않는다

```python
KEY = [l.split('=', 1)[1].strip() for l in open('.env', encoding='utf-8')
       if l.startswith('DATA_GO_KR_KEY=')][0]
```

`.env` 는 `.gitignore`, 저장소에는 `.env.example` 에 **변수명만** 둔다.
공개 저장소에 올라간 키는 커밋을 되돌려도 이력에 남는다.

---

## 3. 403은 재시도하지 말고 멈춘다

```python
if err == 1 and '403' in str(e):
    print('→ 활용신청이 안 된 것으로 보인다. data.go.kr/data/15080648 에서 신청할 것')
    sys.exit(1)
```

인증 실패를 재시도하면 **예산만 태우고 자료는 한 건도 안 쌓인다.**
한도 초과(429)·권한(403)·잘못된 키는 즉시 중단, 네트워크 타임아웃만 재시도한다.

---

## 4. 쓰기 전에 응답 구조를 눈으로 본다

파서를 먼저 쓰면 반드시 틀린다. **응답 하나를 통째로 저장해서 키를 확인한 뒤** 파서를 쓴다.

가장 흔한 함정 — **1건일 때 리스트가 아니라 객체로 온다.**

```python
lst = body.get('busLocationList') or []
if isinstance(lst, dict):
    lst = [lst]            # 이 줄이 없으면 1대 운행 시간대에 조용히 0건이 된다
```

조용히 틀리기 때문에 위험하다. 예외도 안 나고 건수만 줄어든다.

---

## 5. JSONL 로 이어쓰고 즉시 flush 한다

```python
with open(out, 'a', encoding='utf-8') as fo:      # 'a' — 중단돼도 앞 분량은 남는다
    ...
    fo.write(json.dumps(rec, ensure_ascii=False) + '\n')
    fo.flush()                                     # 버퍼에 두면 강제 종료 시 사라진다
```

한 줄 = 한 관측. 수집 도중 끊겨도 쓴 만큼은 분석할 수 있다.
`ensure_ascii=False` 를 빼면 한글이 `\uXXXX` 로 부풀어 파일이 3배가 된다.

---

## 6. 이미 받은 것은 다시 받지 않는다

```python
if os.path.exists(p) and os.path.getsize(p) > 200:
    skip += 1; continue
```

크기 조건이 중요하다 — 실패 응답이 0바이트나 짧은 오류 JSON 으로 저장돼 있으면
"있으니 건너뛴다"가 **빈 파일을 영구히 고착시킨다.**

---

## 7. 필드 의미는 1차 명세로 확인한다

`peekAlloc` 을 이름만 보고 **"첨두 배차"** 로 읽었다. 명세 원문은 **"평일 최소 배차시간"** 이었다.
이 오독 위에 세운 주장 4건을 철회했다.

**필드명·단위·기준시점을 추측하지 않는다.** 명세를 못 찾으면 그 사실을 한계로 적는다.
`nPeekAlloc` 처럼 접두사만 다른 쌍은 특히 위험하다.

---

## 8. 관측창은 주기의 1.5배를 넘겨야 한다

**절단 편향.** 창이 주기보다 짧으면 "완결된 표본"은 빠른 쪽에 치우친다.

| 관측창 | 완주 표본 | 왕복 중앙값 |
|---|--:|--:|
| 155분 | 2대 | 136분 |
| **240분** | **13대** | **150분** (+10%) |

같은 노선, 같은 날이다. **표본 수(n)를 항상 값 옆에 적는다.** n=2와 n=13은 다른 근거다.

시간대로 쪼갤 때도 같다. 구간이 창보다 길면 중간시각 분류는 의미가 없다 —
**연속 관측쌍 중 양 끝이 모두 창 안인 것만** 센다.

---

## 9. 집계 단위가 값을 바꾼다

| 집계 창 | 350번 운행 대수 |
|---|--:|
| 1시간 고유 차량번호 | 23대 |
| **10분 고유 차량번호** | **19대** |

1시간으로 세면 교대·투입 차량이 누적돼 과대계상된다.
**창 길이를 바꿔 몇 번 돌려보고** 값이 어디서 안정되는지 확인한 뒤 고른다.

---

## 10. ID로 묶는다. 이름으로 묶지 않는다

정류소를 이름으로 묶으면 성남에서만 **같은 이름이면서 경유 노선이 다른 102곳**이 뭉개진다.
판교역서편은 세 ID가 각각 마을버스 6개 / 1개 / 0개다.

상·하행도 ID가 다르다. **ID로 다루면 방향이 자동으로 분리된다.**

가공 CSV 를 만들 때 **ID를 공백으로 이어 붙여 한 칸에 넣지 않는다** —
`"205000233 205000234"` 같은 쌍을 그대로 쓰면 조인이 전부 빗나간다(실제로 −1이 나왔다).

---

## 11. 개인정보는 공개 전에 가명화한다

버스위치 API 응답의 `plateNo` 는 **실제 차량번호**다.

```python
# 노선 안에서 정렬해 순번을 붙인다 — 같은 차량은 어느 날짜 파일에서도 같은 가명
m[plate] = f'{route}-{i:02d}'
```

- 값만 문자열 치환한다. 다른 필드·키 순서를 건드리지 않는다.
- 대응표는 **저장소 밖**(`.gitignore`)에 둔다. 저장소만으로는 복원되지 않아야 한다.
- 치환 전후로 **분석 출력을 대조**한다. 차량 식별 키로만 썼다면 모든 수치가 같아야 한다.
- **커밋 이력에는 남는다.** 이미 푸시했다면 새 커밋으로는 못 지운다.

사람 이름·이메일·연락처가 든 산출물(신청서 등)은 애초에 `.gitignore` 로 막는다.

## 12. 환경 함정 (Windows + 한글)

| 증상 | 원인 / 처치 |
|---|---|
| 콘솔 한글이 `????` | `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8', errors='replace')` |
| 히어독 안의 `\\`·`\n` 이 깨짐 | Bash 히어독이 백슬래시를 먹는다. **Write 도구**로 파일을 만든다 |
| `python -I` 에서 ModuleNotFoundError | `-I` 는 user site-packages 를 제외한다. numpy·olefile 등이 거기 있다 |
| 한글 경로가 bash→python 인자에서 깨짐 | `glob` + `os.path.join` 으로 코드 안에서 만들거나 PowerShell 을 쓴다 |
| 표준 라이브러리 import 실패 | 작업 폴더에 `struct.py` 같은 동명 파일을 두지 않는다 — 인터프리터가 먼저 집는다 |

## 수집 전 체크리스트

1. **공식 API 가 있는가.** 있으면 크롤링하지 않는다
2. **예산을 계산했는가.** 실행 중에도 세는가
3. **키가 `.env` 에 있는가.** 저장소에 `.env.example` 만 있는가
4. **응답 하나를 저장해 구조를 봤는가.** 1건일 때 dict 로 오는가
5. **관측창이 주기의 1.5배를 넘는가**
6. **필드 의미를 명세 원문에서 확인했는가**
7. **개인식별 값이 섞여 있는가.** 공개 전 가명화 계획이 있는가

## 결과를 내보내기 전

- **표본 수(n)와 관측창을 값 옆에 적는다**
- **수집 방법·기간·기준시점·주요 변수·이용조건**을 결과물에 밝힌다
- **같은 값을 서로 다른 방법으로 구한 것끼리 비교하지 않는다** — 한 노선은 외삽, 다른 노선은 실측이면 비교가 성립하지 않는다
- 추정값과 실측값을 **같은 표에 섞지 않는다.** 섞어야 하면 열을 나누고 표시한다
